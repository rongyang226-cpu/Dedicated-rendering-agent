# 绘 · Android VPN 客户端 0.32.2

分支：`hui-proxy`。原 Android 桌宠模块及莹宝 APK 已从此分支移除；绘沿用包名 `com.yingbao.app`。VPS 上的机器人与后台仍在运行，不属于 Android 客户端删除范围。

**安装说明**：旧莹宝 APK 的签名与当前绘的构建签名不同。安卓拒绝直接覆盖安装，需先卸载旧莹宝后再安装绘，卸载会删除旧 App 的本机数据。未取得旧签名密钥口令之前，不得宣传为可直接升级。

## 当前已实现的代码（待真机验收）

- Mihomo Android arm64 原生库通过固定版本、SHA-256 核验取得；核心库基于 GPL-3.0，绘 Android 模块按 GPL-3.0 发布。
- 用户授权 VPN 后，由前台 VpnService 建立 IPv4 TUN，内核检查 Mihomo YAML、载入配置，并通过回调保护内核 socket；未配置 IPv6 路由或 DNS，安卓默认阻断 IPv6。
- 首页分别显示配置检查、VPN 建立和错误状态；仅 TUN 建立成功时显示「VPN 已建立 · 请核对出口与 DNS」。内核 native TUN 启动错误可能只写日志，不能据此宣传「已验证可用」。
- 使用半身竖屏壁纸和高清头像；常规设备加载 2160×3840 背景，低内存设备加载 1080×1920 背景。
- 在“设置 → 外观”从手机选择本机背景或恢复默认，导入会检查格式、尺寸和大小，并压缩到适合手机显示的范围。
- 从系统文件选择器导入最多 1 MB 的 JSON/YAML 文件；文件只保存在应用私有空间。
- JSON 导入时检查 UTF-8、语法和顶层代理配置字段；Mihomo YAML 在连接前交给核心校验，JSON 仍是草稿。
- 导入采用临时文件和同目录替换，读取配置在工作线程执行；可以选择草稿或删除。
- 规则、全局、直连模式写入临时生成的 Mihomo 配置，并交由核心校验；原始导入文件不改动。规则模式仍使用导入配置的规则。
- Android VpnService 负责 TUN，生成配置会关闭导入文件的桌面 TUN，避免同时启动两个 TUN 监听。
- DNS 来源可选原配置、AliDNS DoH 或 Cloudflare DoH；53 端口严格拦截可单独控制。修改只在下次连接生效。浏览器内置加密 DNS 不在 53 端口拦截范围内。
- 规则编辑、测速、连接列表和 sing-box 选项尚未接入时继续禁用，不展示虚假数据。

## 下一步实现顺序

1. 用手机实测核心 TUN 启动、出口、DNS/IPv6/UDP、断线及权限拒绝；内核的 TUN 错误目前没有可靠 Java 成功回调，需以真机检测补齐状态确认。
2. 做订阅缓存与错误处理、网络切换和状态日志，再逐项开放节点测速等功能。
3. 接入 sing-box 作为第二内核；Xray 属于后续扩展。
5. 高级分流、测速、流量、连接和诊断须从核心获得真实数据，逐项完成回归。

后台目前提供账号/设备和订阅生成接口；绘还未调用这些接口。服务端运行的 sing-box 不等于 Android 已集成内核。

## 依赖与构建

构建脚本 `scripts/build.sh` 固定下载 `oviron/libmihomo-android v0.3.5` 与 Kotlin 标准库 2.2.10 并核对 SHA-256；打包 arm64-v8a so。源码与 GPL-3.0 许可随本仓库及 APK 提供。第三方内核的启动回调限制、版权和版本详见该库的官方仓库。
